# 白酒半年报问答库｜作业3 · 方向A

本项目读取10家A股白酒公司的2026年半年度报告全文，使用真正的语义嵌入模型与BM25检索，再由本地大模型生成带出处的答案。修订重点是恢复表格列标题、逐家公司取证，并把“召回了正确材料”与“实际答案正确”分开评价。

[一页结论](conclusion.pdf) · [完整页面截图](screenshot.jpg) · [10题实际答案及所有已读块](evaluation.md) · [完整运行记录](evaluation_records.json)

## 实测结论

固定10题：8道单公司题、2道10家公司全景题。先保存模型输出，再用独立核对的原始PDF答案评价。

|评价对象|结果|含义|
|---|---|---|
|已读证据是否满足本题义务|10/10|对这10题检查所需原文是否读到，不是通用检索召回率|
|完整正确的页面实际答案|8/10|9道有明确答案的题中8道正确|
|研发投入题|部分正确|拒绝用费用冒充投入，但口径解释不足，严格评价未通过|
|归母净利润全景题|失败|10家公司证据齐全，模型仍抄错茅台数字并生成无效引用，页面拦截错误答案|

单公司明确指标题、销售模式题、营收全景题答得较好。难点是相近财务口径与跨公司长答案的复制准确性。第10题模型把茅台44,516,880,421.86元抄成4,451,688,042.18元，不能因正确数值出现在证据中就判回答正确。

首轮真实运行仅4/10完整正确，原始输出、错误及记录保留在[history/first_run](history/first_run)。修正提示词和取证范围后重跑同一题集，最终结果如上。该题集已用于修改系统，属于固定题集的开发核对，不能视作未知题目的泛化成绩。拒答拦截减少错误展示，但失败题依然计为失败。

## 数据与表格

来源均为巨潮资讯公开披露的**全文PDF**，不是摘要；公司为贵州茅台、五粮液、泸州老窖、山西汾酒、洋河股份、古井贡酒、今世缘、舍得酒业、酒鬼酒、口子窖。官方地址见[sources.json](sources.json)，文件SHA256、页数及块数见[source_manifest.json](source_manifest.json)。本次重新下载10份文件，与本地原件的哈希全部一致，记录见[remote_source_check.json](remote_source_check.json)。

逐页保留公司、股票代码、报告期间、章节、PDF页码、表名、单位和出处；正文约650字符切块并保留一行重叠。表格按行切块，合并多层表头，去除虚假空列，修复换行指标名；同一张表中遇到新的期间表头时重置，跨页仅在相邻页、列数匹配且位置连续时继承。证据同时展示本期、上期和同比列，不能只留数字。页码统一使用PDF阅读器页码，原始PDF直链附带`#page=`。

当前共有14,953块（2,588个正文块、12,365个表格行），其中2,902行的复杂表头仍未可靠恢复；明确标记未解析，并从最终表格证据选择中排除。10家公司摘要财务表以及本次评测实际使用的行已与原页核对。没有声称全部复杂表格都已无损恢复。原始页级文字和表格网格保存在本地`data/pages.json`。

## 检索与生成

1. 嵌入：`BAAI/bge-small-zh-v1.5`，CLS向量归一化，512维；查询按模型说明加入检索指令。不是把词频向量称为语义嵌入。
2. BM25：SQLite FTS5，中文词/字组合检索，与向量候选进行RRF融合。
3. 取证：明确公司题限定公司；全景题为10家公司分别检索，避免全局Top-k只覆盖几家公司。明确财务指标还按指标名称、完整表头和本期列定位主要会计数据表。此定位只读表格标签，不读gold答案。评测保留两路Top-60候选ID、定位候选、最终已读块。
4. 回答：`Qwen2.5-7B-Instruct`的本地MLX四位量化版，temperature=0。模型只收到问题、证据义务和本轮已读原文。回答及逐公司行由模型实际生成；没有把标准答案写进网页。
5. 检查：引用须来自本轮证据，行内金额须存在于自身证据，公司和期间须对应，研发费用不能换名为研发投入。未通过时保留原始输出并显示拒答。该检查不等于完整财务语义校验，最终正确性另由评价核对单位、指标、期间和原页。

页面提供实时提问、原页引用、本地PDF，以及已保存10题实际记录的查看入口。查看记录不会伪装成新的模型调用。

## 本地运行

实测环境为Apple Silicon macOS、Python 3.12；回答模型运行依赖MLX。首次模型下载约数GB，需要网络和足够内存。无需API密钥。

```sh
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python setup_models.py
python pipeline.py download
python pipeline.py extract
python pipeline.py build
python app.py
```

浏览器打开 `http://127.0.0.1:8767`。下载与索引生成文件位于`reports/`、`models/`、`data/`，已忽略提交；仓库内的源地址和脚本可以重新生成。两模型下载固定版本，见[setup_models.py](setup_models.py)。

```sh
python evaluate.py
python make_conclusion.py
```

`evaluate.py`与网页调用同一个`QA.ask`，完整保存实际输出到`evaluation_ungraded.json`之后才加载`gold.json`核对。已交付记录追加了逐题原页人工复核说明；重新运行会产生新记录，模型环境变化可能改变输出，不能预先承诺同一分数。`evaluation_records.json`含模型原始文本、校验前结果、最终页面结果、全部已读原文和检索轨迹；`evaluation.md`为阅读版，`gold.json`仅供评价使用。

## 文件与边界

- `pipeline.py`：下载、抽取、表头恢复、嵌入及BM25索引。
- `engine.py`：问题路由、逐公司检索、模型生成、证据检查。
- `app.py` / `index.html`：本地服务及问答界面。
- `evaluate.py` / `gold.json`：实际运行与独立评价。
- `build_info.json`、`source_manifest.json`：本次构建统计和数据出处。
- `conclusion.pdf`、`screenshot.jpg`：提交附件。

报告数字会更新，RAG适合可追溯的事实问答；微调可用于学习稳定的回答格式，但不能替代原始数字与出处核对。本次没有把课堂中的其他法规库示例照搬为任务要求，也没有声称实现GraphRAG或微调。
